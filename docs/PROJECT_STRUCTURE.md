# Карта проекта

Открывайте в VS Code папку Apps3. Рабочий исходный код находится в src, backend и desktop. Папка build создаётся сборкой и не редактируется. Старый макет перенесён в Practice_3/archive/mockup-v0. Документация лежит в docs.

│   │   ├── ProfilesPage.jsx       # выбор профиля

## Как проходит действие

Страница или компонент вызывает api.js. Electron передаёт команду в Store, который собирает Connection, репозитории и WorkspaceService. Сервис проверяет принадлежность профилю, использует DTO для проверки входных данных и выполняет операцию через репозитории. Мапперы готовят результат для интерфейса.

Сервисы разделены по профилям, курсам, студентам, заданиям и сдачам. WorkspaceService управляет командами, общей транзакцией и сборкой состояния. SubmissionService отдельно управляет загрузкой и подготовкой копии: запись файла и транзакция базы имеют разные этапы восстановления.

## Репозитории, DAO, DTO и мапперы

- **Репозитории** содержат именованные SQL-запросы. Например, assignments-repository.js получает версии задания и сохраняет критерии. FileRepository сохраняет и читает оригиналы, проверяет контрольную сумму.
- **DAO:** отдельные классы с теми же методами не добавлены. Сейчас задачи доступа к данным выполняют Connection и репозитории. Connection отвечает за SQLite, репозитории — за запросы к сущностям. Дополнительный слой имеет смысл при появлении самостоятельной ответственности.
- **DTO** — обычные объекты JavaScript. Функции в dto проверяют и нормализуют данные команды перед сохранением: ограничения текста, год, форму обучения, критерии, размер и имя файла. Принадлежность курса и версии проверяют сервисы.
- **Мапперы** переводят представление базы в данные интерфейса: например, group_name → group, half_points → points. Они не читают базу и не записывают файлы.

## Где менять код

| Что меняется | Где искать |
| --- | --- |
| Экран или вкладка | src/pages |
| Общий элемент или форма | src/components |
| Правило выполнения действия | backend/services |
| Проверка полей команды | backend/dto |
| Форма ответа интерфейсу | backend/mappers |
| Запрос к базе | backend/repositories |
| Новая таблица или столбец | новая миграция в backend/database/migrations |
| Обработка содержимого ноутбука | backend/domain |

В React не добавляем SQL или прямое чтение файлов компьютера. В репозитории не добавляем решения о том, можно ли преподавателю выполнять действие: это ответственность сервиса. Транзакция создаётся вокруг всего сценария, а не отдельно для каждого SQL-запроса.

Текущая схема базы — версия 8. Миграция 008 добавляет инфраструктуру ИИ с mock-поставщиком. Формальные проверки добавлены миграцией 007; пароли, оценки и внешние идентификаторы — 004–006. Миграция 003 добавляет журнал назначений автора, статусы копий, мягкое удаление работ и активность участия в группе. Миграции 001 и 002 не изменяются; новые миграции добавляются в конец списка в connection.js.

## Форматирование и проверки

```sh
npm run format
npm run format:check
npm test
npm run build
npm run test:electron
```

Prettier установлен как зависимость разработки с закреплённой версией. При добавлении кода используйте форматирование проекта. Проверка Electron использует отдельную временную базу, проходит по страницам и формам, открывает исходный текст и сохраняет подготовленную копию.
