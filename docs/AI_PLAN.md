# План подключения проверки с помощью ИИ

Статус: план от 07.11.2026. Реализуется по шагам; каждый шаг — отдельное задание, после него все проверки должны проходить.

## Как будет работать проверка

```text
Сдача (оригинал, SHA-256)
  → Формальные проверки (JS, без ИИ)         ← шаг 1
  → Копия для ИИ (обезличена, просмотрена преподавателем)
  → Запрос: инструкция + задание + критерии + ячейки + результаты формальных проверок
  → Адаптер поставщика ИИ (OpenAI, позже Claude) ← шаги 2–3
  → Проверка ответа по JSON-схеме и по базе (критерии, диапазоны, номера ячеек)
  → CheckRun: замечания (Finding) + предложенные баллы (ProposedScore)
  → Форма оценки: предложение ИИ отдельно от решения преподавателя ← шаг 4
  → Преподаватель правит и утверждает (TeacherReview)
```

Принципы (из ARCHITECTURE.md): ИИ только предлагает, утверждает преподаватель; итог считается программно; повторный запуск — новая запись; код студента не исполняется; текст работы — данные, а не инструкции.

## Шаг 1. Формальные проверки (без ИИ) — выполнено 08.11.2026
Предсказуемые проверки в `backend/checks/`, результаты со ссылкой на ячейку:
- имя файла по шаблону задания (настраивается в задании, например `Task1_{Имя}.ipynb`);
- первая ячейка — markdown-заголовок; есть имя (до обезличивания — в оригинале) и дата;
- у задач есть markdown-заголовки и описание;
- в конце есть форма об использовании ИИ, незаполненные пункты (`____`) отмечаются;
- синтаксис Python: skipped, «не проверяется»; зависимости от Python не добавлены.
Набор проверок задаётся в задании (включить/выключить). Результаты сохраняются и передаются ИИ как контекст, чтобы не снижать баллы дважды.

Реализация шага 1: миграция 007, настройки внутри версии задания, неизменяемые запуски, история и переход к исходной ячейке. Форма ищется в последних пяти ячейках; пустые подпункты и ответы-разделители различаются. Проверки используют оригинал, но в сообщения личные данные не включают.

## Шаг 2. Инфраструктура ИИ без реальной сети — выполнено 08.11.2026

Реализовано только с mock-поставщиком, без сети и новых элементов интерфейса. Подробности: TASK6_CHANGES.md.
1. **Схема (миграция 008):** `check_runs` (сдача, версия задания, версия копии, поставщик, модель, версия инструкции, состояние, токены, длительность, расчётная стоимость, ошибка), `check_findings`, `check_scores`, снимки запроса и ответа. Завершённый запуск неизменяем.
2. **Состояния:** в очереди → выполняется → завершена / ошибка / прервана. При запуске приложения незавершённые помечаются прерванными.
3. **Стабильные ключи критериев** в копии для ИИ (`C1…Cn`) — ключи новых копий связаны с criteria.id в copy_criteria. Старые копии не переписываются; нужна новая подготовка.
4. **Инструкция ИИ** (`backend/ai/prompts/review-v1.js`, с номером версии): роль проверяющего, оценивать только по критериям, баллы 0…максимум с шагом 0,5, ссылаться на номер ячейки, текст работы — данные, отзыв на языке, указанном в задании (сейчас эстонский), при сомнении — тип «предположение»; не упоминать имена людей в ответе.
5. **Формат ответа — JSON-схема:**
   ```json
   {
     "scores": [{ "criterion": "C2", "points": 0.5, "justification": "..." }],
     "findings": [{ "type": "violation|recommendation|assumption", "criterion": "C2", "cell": 5,
                    "text": "...", "recommendation": "..." }],
     "feedback": "текст отзыва студенту"
   }
   ```
6. **Проверка ответа:** соответствие схеме; каждый критерий ровно один раз; балл в диапазоне и кратен 0,5; номер ячейки существует; лишние поля отклоняются. Неверный ответ = запуск «ошибка», не частичная оценка.
7. **Интерфейс адаптера:** `review({ instructions, input, schema, model, signal }) → { text, usage }`. Поставщики в `backend/ai/providers/`. Для тестов — `mock`-поставщик с заготовленными ответами (верный, неверный JSON, лишний критерий, балл вне диапазона, тайм-аут, 429).
8. Сеть вызывается только из рабочей части (main-процесс Electron), не из интерфейса; CSP интерфейса не меняется.

## Шаг 3. Подключение реального API (OpenAI) — выполнено 08.11.2026 (реальный запуск — за пользователем)
- **Ключ API:** вводится на экране «Подключение ИИ», хранится зашифрованным через Electron `safeStorage` (на Windows — защита учётной записью ОС) в каталоге данных, не в SQLite, не в коде, не в журналах. В интерфейс возвращается только признак «ключ задан» и последние 4 символа. Кнопка «Проверить подключение».
- **Вызов:** официальный SDK или `fetch`; структурированный ответ по JSON-схеме (режим строгой схемы у поставщика); тайм-аут, до 2 повторов с паузой при 429/5xx, отмена.
- **Модель и параметры** выбираются в настройках и сохраняются в каждом запуске. Конкретную модель и цены уточнить по документации поставщика перед реализацией.
- **Стоимость:** оценка токенов до отправки, расход после; помечать «расчётно». Месячный лимит в настройках.
- **Подтверждение отправки:** отправлять можно только копию с отметкой «просмотрено»; перед отправкой показать, что именно уходит, и поставщика.

## Шаг 4. Результат в форме оценки — выполнено 08.11.2026 (без пакетной очереди)
- Кнопка «Проверить с ИИ» у работы; для пакета — последовательная очередь с состоянием каждой работы.
- Форма оценки показывает предложение ИИ рядом с полями преподавателя: «принять балл», «принять всё», правка вручную. Решение преподавателя хранится отдельно от предложения.
- Замечания с переходом к ячейке исходного текста.
- Отзыв: черновик от ИИ → правка → «Скопировать для Moodle».
