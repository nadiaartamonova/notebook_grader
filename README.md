# Практикум

Структура исходного кода и назначение слоёв: [Карта проекта](docs/PROJECT_STRUCTURE.md).

Локальное приложение преподавателя. Реализованы профили, курсы, карточки студентов, задания, критерии, версии правил, загрузка ноутбуков, повторные сдачи и подготовка копии для ИИ. Интерфейс — React на JavaScript; рабочая часть — Node.js; хранение — SQLite; оболочка — Electron.

## Рабочая версия и архив

**Рабочее приложение:** `src/`, `backend/`, `desktop/`, корневой `index.html`. Данные сохраняются в SQLite, а не в localStorage.

**Архивный макет** перенесён из `dist/` в `Practice_3/archive/mockup-v0/` и в Git не входит. Он остаётся образцом согласованного дизайна; его данные хранятся только в браузере и не связаны с SQLite. Дальнейшие изменения интерфейса выполняются в `src/`.

**Материалы вне приложения** (в `Practice_3`, не в Git): `documents/`, `literature/`, `testdata/` — исходные учебные материалы и работы для проверки, `archive/`.

Демонстрационные студенты и оценки не переносятся автоматически. Рабочая база изначально пустая.

## Запуск

Для разработки нужен Node.js 24 или новее и npm. Выполнять в папке `Apps3`:

```sh
npm ci
npm start
```

На текущем компьютере зависимости уже установлены. `Start-Practicum.cmd` собирает интерфейс и открывает Electron. Это запуск из исходников, ещё не установочный пакет.

Просмотр в браузере для разработки:

```sh
npm run build
npm run preview:local
```

Рабочая версия: `http://127.0.0.1:8314`. В Electron обмен идёт через ограниченный IPC-мост без HTTP-сервера. Не редактируйте одну базу одновременно из Electron и браузерного просмотра; основной способ использования — Electron.

## Данные

- `.local-data/practicum.sqlite3` — база разработки.
- `.local-data/files/`, `.local-data/staging/` — оригиналы ноутбуков и промежуточные файлы незавершённого импорта.
- `.test-data/preview/` — отдельная тестовая база при запуске `node scripts/local-preview.js --test-data`.
- В установленном приложении данные будут в пользовательском каталоге Electron, вне исходников.

Данные и зависимости исключены из Git. SQLite использует внешние ключи, WAL и транзакции. Незавершённое копирование курса откатывается целиком.

## Реализовано

- Локальные профили, курсы, фильтры, левое меню дневных и сессионных групп.
- Независимое копирование правил и заданий без студентов и оценок.
- Студенты, необязательный учебный номер, поддержка однофамильцев.
- Задания, критерии, пояснения и дополнительные требования.
- Баллы с шагом 0,5, проверка значений также в рабочей части.
- Неизменяемые версии правил, заданий и критериев; защита от устаревших правок.
- Последовательные миграции с откатом при ошибке. Выпущены миграции № 1, № 2 и № 3; существующие данные сохраняются.
- Карточки студентов с цветом и инициалами; загрузка одного или нескольких .ipynb до 5 МБ каждый.
- Назначение и смена автора с историей; повторные сдачи с сохранением номеров.
- Мягкое удаление работ с сохранением оригиналов и истории.
- Редактирование студентов и исключение из группы без текущих работ.
- Просмотр исходного текста без исполнения кода; редактируемая копия для ИИ с историей правок.

## Текущие ограничения

Формальные проверки, ИИ, реальные отчёты и оценки, утверждение требований, аналитика, резервное копирование и установочный пакет — следующие этапы.

Копия для ИИ готовится локально: исключаются метаданные, выводы, вложения и raw-ячейки; заменяются известные имя и номер студента, части имени из названия файла, почта и некоторые форматы телефонов. Имена сравниваются без диакритики; в коде регистр учитывается, в markdown — нет. Если имя не найдено, показывается предупреждение. Это предварительная минимизация данных, а не гарантия анонимности. Преподаватель просматривает и редактирует JSON. Автоматический поиск не охватывает все формы личных данных и изображений в исходном тексте. Копия не используется для запуска кода. Никаких отправок в ИИ пока нет.

Файл связывается с версией задания на момент импорта. При изменении правил курса сохраните задание заново, чтобы следующие сдачи использовали новые правила. Оригинал хранится неизменным с контрольной суммой SHA-256. Новые импорты сохраняются одной транзакцией базы. При сбое записи базы откатываются; уже сохранённые байты могут остаться на диске без записи в базе. Незавершённые импорты предыдущей версии восстанавливаются после перезапуска; может потребоваться назначить автора заново.

Каждое сохранение задания создаёт неизменяемую версию, включая подготовительные правки. Разделение на редактируемый черновик и утверждённую версию запланировано перед проверкой работ. Пока это история редактирования, а не утверждённых критериев.

После добавления оценок они будут ссылаться на конкретную версию задания. Новый максимум не должен применяться к старым оценкам; диапазон проверяется по критерию использованной версии.

Профили не защищены паролем. ИИ не подключён. Код студента не исполняется. Рабочий интерфейс не публикует WebMCP-инструменты.

## Проверки и версии

```sh
npm test
npm run build
npm run test:electron
```

Тесты используют отдельные временные базы. Проверяются сохранность при повторном открытии, независимость копии, защита истории, устаревшие правки, ошибочные баллы, принадлежность профилю, идентификация студентов, откат транзакций и миграций.

Зафиксированы React 19.3.0, React DOM 19.3.0, Vite 8.3.0, Electron 44.3.0. Дерево зависимостей закреплено в `package-lock.json`; воспроизводимая установка — `npm ci`.

В установленном Electron 44.3.0 проверены Node.js 24.20.0 и SQLite 3.53.4: создание и повторное открытие базы, загрузка интерфейса и вызов через изолированный preload. Прямого доступа `window.require` нет. Совместимость `node:sqlite` нужно повторно проверять при обновлении Electron; API скрыт за слоем хранения.
